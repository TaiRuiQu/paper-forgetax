# ForgeTax 玩法一致性审计

日期：2026-10-29（Asia/Shanghai）。结论：**核心循环与当前公开规则基线一致，但不能称为原作的完整等价实现。** 本次核对源代码、规则测试、仓库研究文档，并重新阅读 Steam 官方商店和开发者公告；没有原作当前版本的实机逐帧或内部数据验证。

## 核心循环

| 系统 | 代码证据 | 结论 |
| --- | --- | --- |
| 先加热，再锻造；热量持续 | engine.js 的 heatAnvilSword / hammer | 一致；2D 将炉火操作合并到铁砧上的剑，省略搬运 |
| 单剑 10 点充能，下一锤开启入神 | hammer / computeDistribution / frenzyDuration | 一致；基础窗口 4 秒，入神移除破碎；原作精确挥锤手感未实测 |

## 已确认的差异及限制

1. **表现与操作是 2D 改编。** 原作是第一人称 3D，具有移动、拾取与物理摆放。本项目采用固定像素场景、点击/拖拽及快捷键，用户已明确要求保留 2D 像素风。
2. **容量为本项目人为限制。** 地面 24 把、贡台 8 把、剑架 3 把；前两项没有官方精确容量证据。溢出保存在待放置队列，需要手动领取；官方 10 月 21 日描述可安全放置后自动恢复。因此不视为完全一致。
3. **少数复杂遗物仍有近似。** 裂开的双镜重复固定价值加成，不能证明与原作“最后一次遗物价值变化”的内部快照和顺序完全相同。多重碎剑保护顺序也为项目固定口径。
4. **刷新价、稀有度权重、整数截断、普通挥锤间隔**采用项目配置，缺少当前原作精确实测。源码 `rerollCost` 使用 `(200 + day×80)×1.7^次数` 并取整。
5. **暂停与云存档属于实现口径。** 菜单暂停入神计时；本项目使用独立账号/SQLite 云存档，无法视为 Steam Cloud 等价。

## 本次发现并修复

- 原教程仅按“下一步”轮播介绍，未验证动作；可在尚未拿剑时结束。现根据真实状态引导拿剑→加热→锻造→献贡→敲铃→进入次日，重进存档按当前局面恢复。
- 首日教学不篡改抽签概率、剑值或供给。足额时先保贡；碎剑后继续换剑；无剑可用时明确解释欠贡与怒气，首日仍可活到第二天。100 个随机种子模拟均活过首日；这不意味着保证随机足额。
- `moveSwordTo` 原来先清空铁砧引用，再检查剑架/贡台是否满。失败会留下位置是 anvil、但 anvilSwordId 为空的剑，还会耗掉入神和回溯会话。现先验证容量和目标，再修改状态；针对三类满容量验证失败事务完全不变。
- 新增可读完再继续的开场叙事，先交代身份、每日供剑、贡税、三次警告和 21 天目标。
- 原三栏加底栏改为连续像素工坊：炉膛、铁砧、库存、商亭、贡台在同一空间层叠。生成场景背景与透明铁砧，不使用原作素材。

## 验证及证据边界

- 既有 63 项引擎/内容/API 测试通过。
- 新增 4 项回归，包含 100 个 seed 的真实首日推进、读档/跳过/重看、失败移动事务保持。
- 隔离 API 与数据库进行桌面 UI 验证，不使用用户的真实存档。
- **自动测试验证本实现的一致性，不证明所有原作数值一致。** 仍需取得原作当前实机或可核验的数据导出才能关闭上述差异。
