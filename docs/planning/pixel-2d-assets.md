# 像素 2D ForgeTax：新手资产准备指南

整理日期：2026-10-28。

已确认的方向：**像素 2D、固定视角工坊、点击／拖拽操作**。本指南列出需要准备的内容与验收方法；其中尺寸、数量、动画帧数均为本项目的起步建议，尚未制作实际素材，也不表示原作采用这些规格。

玩法依据见 [ForgeTax 玩法研究](../reference/forgetax.md)。本指南不替代该文档中的版本与证据说明。

## 1. 现在最重要的事

第一次做游戏，先做出一个可以从开局玩到结算、失败后重开的短流程，再把占位素材替换为正式像素素材。

建议分为三步：

| 阶段 | 要验证什么 | 需要的资产完整度 |
| --- | --- | --- |
| 占位原型 | 剑能加热、挥锤、进入入神、换遗物、献出与跨日 | 色块、文字和简单形状即可 |
| 第一版可玩演示 | 操作看得懂，结果有反馈，能连续玩几天并重开 | 一间工坊、一条示例剑系、少量遗物、基础音效 |
| 接近完整内容 | 21 天与延长天数、更多构筑、九条剑系、图鉴、成就、保存 | 扩充正式图标、外观、界面、演出与音频 |

短流程可以只跑 3—7 天；若缩短契约、调整物品出现日或简化剑外观，应标为演示规则。完整版本再按已研究的原作规则补齐。

**美术不必一次准备齐。** 最先要准备的是一份统一的风格和尺寸约定，以及一小套能在实际画面里验证效果的样本。

## 2. 资产是什么：六类东西

| 类别 | 通俗解释 | 本项目的例子 |
| --- | --- | --- |
| 静态美术 | 单张可显示的图片 | 工坊背景、剑、铁砧、遗物图标 |
| 动画与特效 | 连续图片或由程序控制的视觉变化 | 挥锤、炉火、火花、碎剑、入神 |
| 界面与字体 | 帮玩家操作和看懂规则的组件 | 按钮、物品槽、说明框、概率面板、中文字 |
| 音频 | 操作与结果的听觉反馈 | 锤击、破碎、敲铃、巨龙警告、环境音 |
| 内容数据与文案 | 决定物品和规则怎么工作的表格与文字 | 价格、概率、贡额、触发条件、教程 |
| 工程资源 | 让素材能被游戏正确使用的说明与配置 | 图片尺寸、动画时长、锤击落点、资源编号、存档格式 |

例如，一张“开裂的接合片”图标只是静态美术。可用的遗物还需要名字、说明、价格、出现条件、触发逻辑、层数显示和验证案例。

## 3. 第一版最小资产清单

以下是准备范围建议，按“独立资产或动画组”计数，不把所有动画帧直接相加。背景和角色可以先用占位图。

| 类别 | 第一版建议量 | 具体内容 | 优先级 |
| --- | --- | --- | --- |
| 工坊背景 | 1 张，保留分层源文件 | 地面／墙面／窗洞／固定装饰 | 必需 |
| 可交互设施 | 6 组 | 炉火、铁砧、存剑架、遗物售卖机、贡台、贡铃 | 必需 |
| 锤子／手 | 1 组，约 4—6 帧 | 待机、抬起、落锤、收回 | 必需 |
| 普通剑 | 1 条示例剑系，约 3—5 个外观 | 从普通到夸张的外观变化；完整节点后续补 | 必需 |
| 碎剑／残骸 | 1—2 组 | 真正碎裂的视觉、可作为贡品的残骸 | 必需 |
| 遗物图标 | 先做 8—12 个 | 初始候选与演示中会出现的遗物 | 必需 |
| 消耗品图标 | 先做 2 个 | 龙鳞保护、回溯；其他物品后续补 | 次高 |
| 巨龙表现 | 1 组，约 3—4 种状态 | 平静、警告、愤怒、致命结果；可先只画眼睛／头像 | 必需 |
| 幽灵商人 | 1 个头像或小立绘 | 先有静态形象和交易面板 | 次高 |
| 通用界面 | 1 套可复用组件 | 按钮、面板、槽位、提示、进度条、滚动条 | 必需 |
| 通用信息图标 | 约 8—12 个 | 金币、剑币、贡品、充能、保护、锁、刷新、设置等 | 必需 |
| 结果特效 | 约 6—8 组 | 五种锻造结果、保护、入神开始／结束 | 必需 |
| 字体 | 1 套覆盖中文的字体 | 中文说明、数字、百分号、正负号和常用标点 | 必需 |
| 音效 | 约 12—18 个短音频起步 | 锤击、结果、交易、敲铃、警告、点击 | 必需 |
| 环境音／音乐 | 炉火循环 1 段；背景音乐可先 1 首 | 支持长时间听，不遮盖结果提示 | 后补 |
| 数据表与文本 | 一套 | 剑、遗物、消耗品、贡额、教程、提示 | 必需 |

这些是演示范围，不是完整复刻的最终数量。完整遗物内容可从参考文档的 94 条社区记录逐项建立任务，但每件的逻辑与当前版本数值仍需核对。

## 4. 工坊背景应该怎样拆

### 4.1 保留可独立操作的层

建议至少拆成：

1. 后景：墙面、远处、窗外。
2. 建筑／固定环境：地面、梁柱、固定装饰。
3. 可交互设施：炉、铁砧、售卖机、贡台、铃。
4. 物品：剑、残骸、遗物、待领取物。
5. 前景遮挡与灯光。
6. 界面：金币、贡额、概率、按钮与说明框。

**会动、能点、会变状态的东西，最好有独立资源。** 不把铁砧上的剑、炉火动画、商品价格和今天的贡额画死在一张背景上。

### 4.2 设施的状态表

| 设施 | 至少要能表达的状态 | 可以由程序完成的部分 |
| --- | --- | --- |
| 炉火 | 空、剑加热中、剑已就绪 | 加热进度、发光、完成提示 |
| 铁砧 | 空、有剑、正在锻造、暂不能操作 | 悬停高亮、点击区域、状态提示 |
| 存剑区 | 空位、有剑、选中、可接收／不可接收 | 槽位框、选中描边 |
| 售卖机 | 候选存在、买得起、资源不足、遗物槽已满 | 价格、灰显、原因说明 |
| 贡台 | 空、已有贡品、足额、欠额 | 实时合计与差额 |
| 贡铃 | 可结算、结算中 | 防止重复提交、确认信息 |

“状态”不代表每种都必须重画一张完整图。高亮、文字、颜色与进度条可以复用。

## 5. 剑的美术量如何控制

### 5.1 等级不等于独立图片

数值等级由程序显示，外观按少量节点切换。原作当前强化可到 +99，但最终外观停在 +20，所以不需要给每条剑系绘制 99 张图片。

完整范围需要逐条规划九个剑系及其外观节点；共用的早期普通剑外观可复用。第一版先验证一条剑系的成长感。

### 5.2 一把剑需要哪些视觉状态

| 状态 | 建议做法 |
| --- | --- |
| 常温 | 基础剑图 |
| 已加热 | 程序加色或叠加像素发光；必要时补专用热态图 |
| 放在铁砧 | 使用同一资源，加上固定放置点 |
| 拾起／拖动 | 同一资源跟随鼠标，配拖拽反馈 |
| 普通成功／大成功 | 同一剑资源配结果特效和升级反馈 |
| 损伤 | 反馈动作、文字与短特效；是否换外观依据规则 |
| 破碎 | 碎片动画或通用碎片粒子 |
| 受保护 | 护盾／龙鳞破裂等叠加效果 |
| 入神 | 发光、局部背景变化、倒计时、专属特效 |
| 放入贡台 | 使用同一资源，保持身份与实际价值 |

同一把剑从库存拖到铁砧，应仍是同一个物品实例。图可以复用，等级、层数与保护状态不能被意外重置。

### 5.3 画布与定位

建议试用横放的剑，以统一的透明画布交付，例如 128×64 像素；小剑可以占画布的一部分，大剑再使用统一规格的扩展画布。

必须记录剑柄握持点与放置点。动画各帧也要对齐相同锚点，否则挥锤时剑会跳位置。

库存图标需要在小尺寸下依然识别。可以从剑图生成预览后手工修正，不必每次独立重画完整剑，但不能默认随意缩小仍清楚。

## 6. 遗物与消耗品：图标之外的工作

### 6.1 每件物品的交付信息

| 字段 | 作用 |
| --- | --- |
| 稳定 ID | 程序、图标、存档和文本之间的对应编号 |
| 名称与短描述 | 玩家识别和理解 |
| 完整效果说明 | 触发条件、数量、上限、持续时间 |
| 图标路径 | 指向实际图片 |
| 稀有度／类别 | 展示与随机池 |
| 价格与解锁条件 | 决定能否购买、何时出现 |
| 触发范围 | 下一锤、当前剑、每天、本局、跨局 |
| 状态显示 | 层数、剩余次数、待兑现收益 |
| 行为逻辑 | 实际如何改变游戏状态 |
| 验证案例 | 明确什么操作后应该出现什么结果 |

图标与规则分开：数值和说明修改时，不应重新画图。

### 6.2 小图标也要统一

- 使用统一画布，例如 32×32 像素。
- 统一描边宽度、光照方向、阴影深浅和边缘留白。
- 优先保证轮廓差异：钉子、沙漏、杯子、绳结应能区分。
- 稀有度边框可由界面统一绘制，避免在每个图标上重复制作。
- 未发现状态可以由剪影与锁标记生成。
- 不把整段遗物说明、价格或层数画在图标里。

## 7. 反馈和动画：最影响“敲起来好不好玩”的部分

### 7.1 五种结果必须分得清

| 结果 | 视觉反馈建议 | 声音建议 | 必须同步的状态 |
| --- | --- | --- | --- |
| 成功 | 短火花、升级数字 | 清晰锤击＋轻提示 | 等级、剑值、下一锤概率 |
| 大成功 | 更强火花与醒目的结果标记 | 更亮的金属声／和声 | 大成功价值、额外等级、遗物触发 |
| 不变 | 短促轻反馈，文字明确 | 较平的敲击 | 可能仍有遗物收益与充能 |
| 损伤 | 裂纹／回弹／掉级提示 | 沉闷失误声 | 掉级、返级、损伤收益、保护 |
| 破碎 | 剑消失与碎片、破碎文字 | 清楚的断裂声 | 真正破碎、残值、继承、回溯机会 |

颜色只是辅助，同时使用图形、文字和声音。损伤与真正破碎要有明显区别。

### 7.2 起步动画组

| 动画 | 起步建议 | 关键制作说明 |
| --- | --- | --- |
| 炉火 | 4—6 帧循环 | 第一帧与末帧衔接 |
| 挥锤 | 4—6 帧 | 标出抬起、接触、回收；落点明确 |
| 火花 | 3—5 帧 | 透明背景，可在不同锤击位置复用 |
| 碎剑 | 4—6 帧或程序碎片 | 不用为每把剑都单做同样的碎裂动画 |
| 巨龙眼睛／头像 | 少量眨眼和怒气变体 | 优先建立威胁感与警告可读性 |
| 入神 | 开始、持续、结束三种反馈 | 结束后玩家必须看得出普通风险恢复 |

帧数是制作建议，游戏计时由程序控制。美术动作与锻造结算要在同一个接触时刻对应，不能先播放成功音效再过很久才显示结果。

### 7.3 哪些效果可以由程序复用

常见可复用项包括短暂变亮、轻微震动、颜色变化、描边、数字弹出、进度条、护盾叠层和背景变色。

这些效果不必全部预先烘焙成大图；但应使用与像素画风一致的移动和采样方式。玩家还应能降低闪烁和屏幕震动。

## 8. 界面和中文字体

### 8.1 第一版需要的界面

| 界面 | 必要内容 |
| --- | --- |
| 开始／暂停 | 新游戏、继续、音量、显示、退出 |
| 主工坊状态 | 当前日、金币、剑币、贡额、怒气 |
| 锻造面板 | 当前剑、等级、剑值、五结果概率、充能、入神时间、保护 |
| 库存与贡台 | 哪些剑被保留、哪些已献出、台上总值与差额 |
| 遗物商店 | 三候选、效果、价格、购买和刷新 |
| 遗物栏 | 八槽、已装备、可丢弃、状态提示 |
| 商人 | 商品、剩余库存、当前价格、购买结果 |
| 结果画面 | 本日贡值、金币、警告、次日；最终成功／失败与重开 |
| 教程提示 | 当前应做什么、为何暂不能操作 |

图鉴与完整成就页可后续加入；早期至少保留发现／解锁所需的数据。

### 8.2 通用组件要交付哪些状态

按钮：正常、鼠标悬停、按下、禁用、键盘焦点。

物品槽：空、有物品、选中、可放入、不可放入、锁定。

提示框：名称、效果、价格、触发状态；长文字可换行或滚动。

可伸缩面板：边角保持原像素尺寸，中间与边缘按规则扩展；常见做法称为“九宫格面板”。

这些状态可以共用基础边框与程序效果，通常不需要每个按钮单独画完整图片。

### 8.3 中文是必须提前验证的资产

字体需包含简体中文、英文、数字和符号。只支持英文字母的像素字体不能完成本项目。

首批素材应在真实大小下试排：

- 破碎概率 29.7%
- 今日贡额：232,000 G
- 每次损伤，为本剑下一次大成功储存额外 1 级
- 下一批供给 +2 把；剩余保护 1 次

需要验证缺字、模糊、标点、自动换行、长名称与大数字溢出。美术可以保持像素风，文本优先保证清楚；不要为了字形像素化把中文压到读不清。

Noto CJK 可作为中文覆盖的候选，其字体使用 SIL Open Font License 1.1；实际采用时保留对应版权与许可文件。是否作为最终字体仍应通过真实尺寸试排。[官方许可](https://github.com/notofonts/noto-cjk/blob/main/Sans/LICENSE)

### 8.4 信息不能混在一起

金币、剑币、单剑价值、贡台合计和当日需求要清楚区分。尤其：

- 高价值剑投入售卖机通常仍只换一个剑币。
- 账户里有金币，不等于贡台上已放够贡品。
- 入神“不破碎”不等于“每锤升级”。
- “不能购买”应显示原因：剑币不足、遗物槽已满或商品不可用。
- 鼠标悬停的信息框不应遮住正在操作的剑或关键概率。

## 9. 像素规格先约定，再批量制作

以下是适合试做的候选规格，并非已确定的最终美术规范。

| 项目 | 起步建议 |
| --- | --- |
| 场景设计尺寸 | 640×360 像素，16:9 |
| 常用显示尺寸 | 1280×720（2 倍）、1920×1080（3 倍） |
| 遗物／消耗品图标 | 32×32 透明 PNG |
| 小型资源图标 | 16×16 或 24×24，选择后同类统一 |
| 常用剑画布 | 例如横向 128×64，握柄锚点一致 |
| 配色 | 先选一套约 16—32 色的主色板，再按材质少量扩展 |
| 光照 | 约定一个主光方向；炉火的局部暖光可额外叠加 |
| 描边 | 同类资产采用相同规则，不要求所有材质都一圈纯黑 |
| 文件 | 源文件＋原始大小透明 PNG；动画另交时长与帧信息 |
| 采样 | 像素图采用最近邻等适当过滤，避免无意模糊 |
| 缩放 | 尽量整数倍，避免不同素材像素颗粒大小不一 |

640×360 和整数倍放大可参考 [Godot 官方多分辨率说明](https://docs.godotengine.org/en/stable/tutorials/rendering/multiple_resolutions.html)。该建议适用于像素场景，字体和复杂界面的分辨率方案仍需按可读性验证。最近邻过滤的含义见 [CanvasItem 文档](https://docs.godotengine.org/en/stable/classes/class_canvasitem.html)。

不需要现在就在 640×360 上画完整房间。先试一小块：铁砧＋一把剑＋一次挥锤＋概率与文字。尺寸不合适时改这一小块，成本最低。

## 10. 美术文件怎么交付才方便接入

### 10.1 静态图片

交付原始像素大小、透明背景的 PNG，并保留可编辑源文件。

对背景保留分层；对物品记录名称、画布尺寸、实际图形占用区域、锚点和用途。展示截图不能替代可直接使用的透明资源。

### 10.2 动画

至少交付：

- 可编辑源文件。
- 单帧 PNG 序列或精灵图集；精灵图集指把多帧排在同一张图片上。
- 每帧时长、帧序、是否循环。
- 动画名称，例如 idle、strike、break。
- 接触帧或关键时刻，例如锤子真正敲到剑的那一帧。
- 每帧一致的锚点；图集裁切后也必须能恢复原位置。

例如可以约定单排图集和统一单帧尺寸；不强制一定使用 JSON，具体由选定工具与引擎的导入方式决定。

Aseprite 支持按动画标签导出精灵图，制作与导出方法见 [动画说明](https://www.aseprite.org/docs/animation/)与[精灵图集说明](https://www.aseprite.org/docs/sprite-sheet/)。GIF 可以用于预览，接入游戏时应同时提供源文件或图集。

### 10.3 音频

优先保留 WAV 原始文件；游戏内是否转为 OGG 等格式，在选择引擎和目标平台后统一处理。

每个音频标明：用途、是否循环、循环点、是否有多个变体、来源和许可。不要让文件开头留很长静音，导致点下去明显晚响。

### 10.4 来源与授权记录

每个外部素材记录作者、来源链接、许可及署名要求，字体和音乐也包含在内。使用原创、委托交付或明确允许项目用途的素材，并保留许可文件。

参考原作玩法与美术方向时，应另行制作本项目的图像、界面与音频。委托美术也应把可修改源文件、使用范围和交付规格说清楚。

## 11. 声音的最小清单

| 类型 | 起步内容 | 细节 |
| --- | --- | --- |
| 核心锤击 | 约 3 个轻微变化 | 避免连续敲击完全相同；听感要有力度 |
| 五种结果 | 为成功、大成功、不变、损伤、破碎建立区分 | 可与锤击叠加，避免同一瞬间过响 |
| 入神 | 开始、结束 | 窗口结束必须可察觉 |
| 保护／回溯 | 各一个 | 玩家能确认道具已经生效 |
| 物品与交易 | 拾取／放下、购买／金币 | 可先少量复用 |
| 结算 | 贡铃、足额、欠贡／龙警告 | 帮玩家理解这次结算后果 |
| 界面 | 点击、不可执行 | 不可执行配可见原因 |
| 环境 | 炉火循环 | 保持较低存在感，不盖过结果音 |

第一版可以先用占位声音验证节奏，再替换正式音频。背景音乐可以晚于锤击与结果音制作。

## 12. 不是美术但必须处理的细节

| 细节 | 新手容易遇到的问题 | 应达到的行为 |
| --- | --- | --- |
| 拖拽取消 | 放错位置导致物品消失 | 无效放置回到原位置，物品状态不变 |
| 点击区域 | 小像素图很难点中 | 可交互范围比细剑刃更宽，悬停有反馈 |
| 拖拽与点击冲突 | 拖剑时误触挥锤／购买 | 输入动作有明确开始、取消和完成 |
| 动画锁定 | 连点在同一锤里结算多次 | 一次有效挥锤只结算一次 |
| 遗物触发 | 动画显示收益，实际数值没变 | 结果、数值、说明与音效一致 |
| 多重保护 | 挡一次碎剑却扣掉两种保护 | 明确触发顺序和消费规则 |
| 回溯 | 恢复了剑，却保留碎剑奖励 | 一起处理金币、签、复制、保护和继承 |
| 贡台结算 | 重复点击铃导致重复发钱／跨日 | 一天只结算一次 |
| 数值增大 | 高等级剑溢出或金额挡住按钮 | 计算范围与显示范围都明确；必要时缩写并可查看完整值 |
| 暂停与切出窗口 | 入神倒计时行为不一致 | 明确菜单、切出、回溯对计时的影响 |
| 存档 | 剑还在但层数／加热状态丢了 | 每把剑的状态、本局状态、跨局解锁分别保存 |
| 空资源 | 没剑没钱时玩家不知道能做什么 | 明确下一步、结算后果或重开入口 |
| 首次教程 | 玩家不懂三种资源 | 分步教加热、锻造、贡台、敲铃和买遗物 |
| 多分辨率 | 换屏幕后按钮点位错、字太小 | 显示与输入坐标都适配，并可读 |
| 无声／低色辨识 | 只靠声音或红绿判断 | 重要结果都有文字或形状辅助 |

这些工作可以由程序和数据承担，不需要你先画出每个中间状态。第一版也应为规则验证预留固定结果、快速补资源和跳转天数的开发工具，避免靠随机运气等某个情况出现。

## 13. 推荐的文件组织

目录目前只是建议，不代表已经创建全部目录或制作素材。

~~~text
assets/
  art/
    source/           可编辑源文件
    backgrounds/      工坊与背景
    stations/         炉、砧、贡台、铃等
    swords/           按剑系／外观节点分组
    relics/           遗物图标
    consumables/      消耗品图标
    characters/       巨龙、商人、手与锤子
    effects/          火花、保护、破碎等
    ui/               通用面板、按钮与信息图标
  audio/
    sfx/              操作与结果音
    ambience/         炉火等循环环境音
    music/            背景音乐
  fonts/
  licenses/           外部资产的许可文件

data/
  swords.*            剑系与外观节点
  relics.*            遗物定义与效果参数
  consumables.*       消耗品定义
  tribute.*           日历与需求
  text_zh.*           中文文本
  asset_manifest.*    资源清单
~~~

data 的具体格式可在引擎确定后选择 CSV、JSON 或引擎自带资源类型。数据可以先用表格理解，不要求你现在学习文件语法。

资源清单至少记录：ID、类别、中文名、文件路径、尺寸、动画帧数与时长、锚点、来源、许可、状态和备注。状态可以用“占位／制作中／待接入／已验证”。

## 14. 你本人现在可以准备什么

### 14.1 准备 3—5 张风格参考

分别表达以下内容，截图或链接即可：

- 希望的工坊气氛与场景密度。
- 喜欢的像素颗粒大小和配色。
- 希望剑成长后有多夸张。
- 喜欢的像素界面与文字清晰程度。

参考图用来解释偏好，不直接作为游戏中使用的素材。

### 14.2 画一张很粗的布局草图

只需要标出炉、砧、库存、遗物商店、贡台、巨龙位置，以及概率和资源信息。纸上方框即可。

现在不追求漂亮，先确认“玩家一眼能找到铁砧，看见剑值，并知道贡品够不够”。最终布局可以在实际可玩原型里调整。

### 14.3 做一个小样

优先准备：

1. 一块铁砧和一把普通剑。
2. 一次挥锤与火花。
3. 三个遗物图标，检查统一性。
4. 一行中文和一段较长说明。
5. 一个可拉伸面板与四态按钮样本。
6. 锤击、大成功和破碎三类试听声音。

把它们放到同一画面、按真实显示尺寸看效果，确认后再成批制作。

### 14.4 暂缓的大工程

完整巨龙身体与战斗动作、铁匠多方向走跑、所有剑形态、94 个正式遗物图标、复杂开场过场和宣传素材，都可以等第一版循环成立后再排。

完整版本最终仍需逐项补齐；“后补”是制作顺序，不是取消用户目标。

## 15. 制作顺序与完成标准

| 顺序 | 交付物 | 完成标准 |
| --- | --- | --- |
| 1 | 占位可玩流程 | 一把剑能完成加热、锻造、入神、进贡；能失败和重开 |
| 2 | 风格与尺寸小样 | 剑、图标、界面和中文放在同一画面里清楚且协调 |
| 3 | 核心正式素材 | 锤击、五结果与入神反馈可读，拖拽位置可靠 |
| 4 | 第一版内容集 | 有初始选择、若干构筑、商人、跨日与短流程结局 |
| 5 | 规则与保存完整 | 关键边界符合参考，读取后物品与局内状态正确 |
| 6 | 全内容扩充 | 按剑系、遗物、消耗品和解锁清单逐项补齐 |
| 7 | 演出与发布素材 | 音乐、更多环境细节、完整图鉴、标题画面和宣传图 |

第一阶段最有价值的投入是让每一锤的操作、结果和风险都清楚。资产规模应随实际可玩版本增长。
