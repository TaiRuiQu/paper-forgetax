- **前端**：零构建步骤的原生 ES Modules + Canvas FX + WebAudio 合成音效。
- **后端**：Node.js 原生 HTTP 服务 + `node:sqlite`，无第三方运行时依赖。
- **存档**：多用户、密码 scrypt 哈希、HMAC 签名令牌、三个云端契约槽位、图鉴/成就跨槽共享。
- **美术**：剑阶/遗物/UI 使用仓库 SVG 像素素材；连续工坊背景和透明铁砧由内置 imagegen 生成后按低分辨率导出。不包含原作素材。提示词与来源记录见 `docs/audit/`。

## 快速开始

要求 **Node.js ≥ 22.5**（使用内置 `node:sqlite`）。无需 `npm install`。

### Windows

双击 `start.bat`，或：

```bat
node scripts\dev.mjs
```

`start.bat` 会在 PATH 中寻找 Node，并兼容 `C:\Program Files\nodejs\node.exe`。

### macOS / Linux

```bash
./start.sh
```

然后打开 **http://127.0.0.1:5173**。首次进入先注册铁匠账号；进度自动同步到云端。

| 服务 | 默认地址 | 说明 |
| --- | --- | --- |
| 前端 | http://127.0.0.1:5173 | 静态界面 + `/shared` 共享引擎 |
| API | http://127.0.0.1:3001/api | 用户、存档、图鉴 |
| SQLite | `server/data/forgetax.db` | 自动创建；已被 `.gitignore` |

启动时自动读取项目根目录的 `.env`，可直接修改后重启；新检出的项目请先将 `.env.example` 复制为 `.env`。系统环境变量优先于文件配置，未创建 `.env` 时使用默认值。

静态服务器会根据 `client/` 和 `shared/` 的文件内容生成资源版本，通过 `/_v/<版本>/` 路径加载脚本、样式、字体和图片（包括动态生成的图片地址）。页面使用 `no-store`，资源使用 `no-cache`；修改文件后刷新页面即可获取新版本，无需手动改版本号或重启静态服务器。根路径和 Caddy 子路径部署均支持。

```dotenv
HOST=127.0.0.1
PORT=3001
WEB_PORT=5173
```

`PORT` 为 API 端口，`WEB_PORT` 为前端端口，两者独立配置。前端默认访问游戏所在路径下的 `api`，由静态服务器转发到配置的 API 端口。若从其它主机访问，请设置 `HOST=0.0.0.0`，通过服务器的实际 IP 访问前端；也可通过 `?api=http://<host>:<port>/api` 手动指定 API 地址（界面按游戏地址记住该配置，优先使用）。

可选环境变量还有 `FORGETAX_DATA_DIR`（数据目录）、`FORGETAX_DB`（数据库文件）、`FORGETAX_SECRET_FILE`（签名密钥文件）和 `FORGETAX_SECRET`（直接指定签名密钥）。相对路径以启动时的工作目录为基准，跨目录启动时建议使用绝对路径。`.env` 已被 Git 忽略，请勿提交真实密钥；可提交的配置模板见 `.env.example`。

### Caddy 子路径部署

页面、样式、动态素材与模块引用均使用相对路径，可部署在 `/` 或 `/forgetax/` 等目录下。目录访问需要末尾斜杠。Caddy 与游戏在同一台主机时，使用 [deploy/Caddyfile](deploy/Caddyfile)：

```caddyfile
game.example.com {
    encode zstd gzip
    redir /forgetax /forgetax/?{query} 308
    handle_path /forgetax/* {
        reverse_proxy 127.0.0.1:5173
    }
}
```

启动游戏后访问 `https://game.example.com/forgetax/`，无需额外代理域名根目录的资源，也无需指定 `?api=`。前端及 API 通过同一个 HTTPS 入口访问；`5173` 应与 `.env` 的 `WEB_PORT` 一致。原有域名配置中已有站点块时，将这些规则合并到现有块中。

## 操作

| 输入 | 作用 |
| --- | --- |
| 点击/拖拽剑 | 放上铁砧、贡台、剑架，或投入售卖机 |
| `Space` | 挥锤（入神中可连续挥锤） |
| `H` | 加热铁砧上的剑 |
| `E` / 右键铁砧 | 取下铁砧上的剑 |
| `X` | 打开丢弃遗物列表 |
| `R` | 使用悔恨发条回溯上一锤 |
| `1`–`5` | 使用铁砧消耗品 |
| `Esc` | 打开工坊菜单 / 关闭弹窗 |
| `P` | 跳过教程 |

窄屏（≤800px 的鼠标窗口，或宽度 <600px 的竖屏触屏）会切换为四个底部页签：**铁砧 / 库存 / 商亭 / 贡台**；铁砧页有固定的加热与挥锤条，「工具」按钮打开消耗品与回溯抽屉。

### 手机（横屏）

手机按横屏游戏设计（高度 ≤540px 的横向视口）：顶部 HUD，左侧四个页签，中间是工坊，右侧是拇指可及的剑况、概率与加热/挥锤按钮。竖握手机进入契约时会提示旋转，并暂停入神与回气计时。

| 触屏操作 | 作用 |
| --- | --- |
| 点按 | 选中剑、使用按钮（无 300ms 延迟，禁用双击缩放） |
| 长按剑并拖动 | 拿起剑，放到铁砧、剑架、贡台、商亭，或左侧页签上；在页签上停留会切换到该页 |
| 长按遗物、道具等 | 预览说明，松手不会触发点击 |
| 按住挥锤 | 入神期间连续挥锤（入神外每次按下只挥一锤） |
| 系统返回手势 | 等同 `Esc`：关闭弹窗或打开工坊菜单，不会直接离开页面 |

- **全屏**：在手机上开始或继续契约时自动进入全屏并锁定横屏（Android Chrome 等支持 Fullscreen API 的浏览器）；HUD、主菜单与登录页都有全屏按钮，设置中可关闭自动全屏。
- **安装到桌面**：提供 `manifest.webmanifest`（`display: fullscreen`、`orientation: landscape`）与 Apple 触控图标。iPhone 的 Safari 不支持网页全屏，请通过「分享 → 添加到主屏幕」从桌面图标启动。
- **震动反馈**：支持 `navigator.vibrate` 的设备在锤击结果、入神、敲铃与拖放时震动，可在设置中关闭。
- 切到后台时计时同样暂停，并挂起音频；刘海与底部手势区通过 `safe-area-inset` 留白。

### 折叠屏与双屏（展开）

展开的折叠屏（三星 Galaxy Z Fold、小米 MIX Fold、Pixel Fold 等，内屏约 1.1–1.4 : 1）、跨屏的 Surface Duo 和小尺寸平板都有专门布局。适用于两边都 ≥541px、宽 600–1180px 的触屏视口。整个工坊同屏显示，不再需要页签：

| 区域 | 内容 |
| --- | --- |
| 左侧（左手拇指） | 剑架与地面库存常驻，底部是选中剑的操作 |
| 中间 | 铁砧、剑况与下一锤概率；竖持时剑况与概率分列铁砧两侧 |
| 右侧（右手拇指） | 「贡台 / 商亭」账本页签，下方是工具、加热与大号挥锤键 |

- **点选放置**：点一下库存或剑架上的剑即「拿在手上」，可放置的位置会亮起虚线框。再点空铁砧、贡台或剑架空位即可放下，再点一次这把剑则放回。左手选剑、右手落位，不必横跨大屏拖动。长按拖动仍然可用，拖到「贡台 / 商亭」页签上停留会自动切换。
- **横竖皆可**：展开时不锁定横屏，转动设备会切换横持与竖持排布；折回外屏时恢复手机布局，全屏中重新锁定横屏。
- **半折叠姿态**（支持 Viewport Segments API 的浏览器，如 Chrome 138+）：
  - **帐篷 / 笔记本**（折痕水平）：上半屏显示铁砧与概率，下半屏放库存、账本与整块挥锤键，折痕处留空。
  - **书本 / 双屏**（折痕竖直）：左页是库存与账本，右页是 HUD、铁砧与挥锤，内容避开铰链。

### API

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `POST` | `/api/register` | 注册并签发 30 天令牌 |
| `POST` | `/api/login` | 登录 |
| `GET` | `/api/me` | 当前用户与全局档案 |
| `GET` | `/api/saves` | 三个槽位（含状态与摘要） |
| `GET` | `/api/saves/:slot` | 单个槽位 |
| `PUT` | `/api/saves/:slot` | 保存状态并合并图鉴/成就/统计 |
| `PATCH` | `/api/saves/:slot` | 按版本校验，只更新有变化的嵌套字段或数组元素 |
| `DELETE` | `/api/saves/:slot` | 删除槽位 |
| `POST` | `/api/profile` | 合并全局档案 |

自动保存以 200ms 窗口合并操作，连续操作不会不断推迟保存。新槽位首次全量写入，之后只上传差异；数组长度改变时整体替换该数组，其余数组变化按元素字段更新。后端使用 SQLite JSON 字段更新，并在同一事务中保存槽位与共享档案。没有变化时不发请求；失败不会推进本地保存基线，重试仍会包含未确认的变化。存档版本冲突返回 409，需要重新载入，避免覆盖其他页面或设备的新进度。SQLite 仍按自身页与 WAL 机制落盘，增量更新不意味着只写几个物理字节。

每个用户的数据在 SQLite 中以 `user_id` 隔离；密码使用随机盐 + scrypt；令牌使用服务端持久化密钥的 HMAC-SHA256。`GET /api/health` 可用于探活。

## 规则口径与已知近似

本次一致性结论与证据边界见 [2026-10-29 玩法审计](docs/audit/gameplay-audit-2026-10-29.md)。开局先展示简短背景叙事，首日教程按真实操作推进到次日；不会修改随机概率来保证足额。新增 100 个随机种子的首日存活验证，以及满容量移动失败的事务回归。

本项目的首要参考是 `docs/reference/forgetax.md`。实现中保留了原文标注的版本差异：21 天、大成功 2.5 倍、+99 上限、+20 最终外观、第 21 天 232,000 G、次日三把基础剑、圣杯初始池、30%/40% 继承、25% 龙鳞钳、40% 凤凰代价等。

公开资料未给出全部结算顺序，以下为本项目的可解释固定口径（均不影响主流程）：

- 多重碎剑保护顺序：裂纹龙鳞 → 凤凰之灰 → 不倒基石 → 铁丝缠鞘 → 巨人脊骨。
- 怨恨之钉的一次性大成功签在抽到大成功时消费；未抽中则保留。
- 商店刷新采用递增金币公式（`200 + 80×天数`，每次付费 ×1.7），社区未公开精确公式。
- 部分复杂遗物（裂开的双镜等）的“重复价值加成”在无法精确复现内部快照时以固定价值形式兑现。
- 2D 化将炉火加热合并到铁砧流程中，但仍强制“先加热再锻造”；剑架/地面为容量化的实体库存，待放置队列保存溢出。
- 中文剑阶名称除参考文档明确给出的最终形外属于本项目译名，英文名保持可检索。

其他未明确的数值（完整商店去重、后期权重、多保护消费顺序、整数截断）都以 `C` 级实现建议处理，并保持可替换的数据/函数边界。

## 生产部署提示

默认配置面向本机单机试玩：CORS 为通配、API 不做游戏规则防作弊（状态由客户端提交），请勿直接暴露到公网。如需公开部署，建议：

1. 配置反向代理、HTTPS、强随机 `FORGETAX_SECRET`、限定 `Access-Control-Allow-Origin`；
2. 增加登录限流、状态 schema 校验/签名与备份（`server/data/forgetax.db`）；
3. 若需要服务端权威结算，将 `shared/engine` 搬入 API，并由服务端生成/校验每一步动作。
